# Windows / Android 定制客户端

本客户端基于 RustDesk 1.4.9（`6c578292e8ebbbec708b76986ba8c4bc7c509747`），配套当前 RustDesk Server OSS 1.1.16 WSS 修改版。只构建 Windows x64、Android `arm64-v8a` 与 `armeabi-v7a`。

## 已实现的连接策略

默认 Cargo feature `custom-wss` 启用共享库的 `strict-wss`。服务器配置编译在 `libs/hbb_common/src/deployment.rs` 中：

| 配置 | 值 |
| --- | --- |
| ID / 中继服务器 | `remote.yingluozhiwei.cn` |
| HTTPS 地址 | `https://remote.yingluozhiwei.cn` |
| 信令入口 | `wss://remote.yingluozhiwei.cn/ws/id` |
| 中继入口 | `wss://remote.yingluozhiwei.cn/ws/relay` |
| 公钥 | 现有实例公钥，保留于上述源码；不包含服务器私钥或访问密码 |

配置 getters 优先返回编译期部署策略，旧配置、导入配置、EXE 文件名和运行时覆盖值不能切换服务器。连接入口只接受部署域名、443 和两条固定路径，拒绝用户信息、查询参数、fragment、异常端口及其他域名。

定制模式使用设备 ID 和中继。关闭 IP/域名端口直连、P2P、UDP/IPv6 STUN、LAN 发现及原生 TCP/UDP 回退。关闭 OSS 服务端没有实现的后台 Pro API 同步和官方客户端自动更新，避免不同版本覆盖定制行为。远程桌面、文件传输等上层功能继续复用上游实现；尚未完成真实设备会话验收。

## TLS、帧大小与发送时序

- Windows 使用 `native-tls 0.2.18` 的 Schannel 与系统证书存储；最低 TLS 1.2，支持 TLS 1.3 的 Windows 系统可协商 TLS 1.3。Android 使用 Rustls 与 Android 平台证书验证器，保持上游 JNI 初始化流程。
- 严格模式不读取无效证书缓存，也不在错误时接受无效证书。证书过期、域名不匹配或不受信任时返回连接错误。
- HTTP Upgrade 使用 HTTP/1.1。Rustls ALPN 仅声明 `http/1.1`，Windows 不声明 HTTP/2。
- 每个 WebSocket 数据帧有效载荷最大 16 KiB。超过上限的消息通过 RFC 6455 Binary + Continuation 分片，保留完整 protobuf/端到端加密消息边界；不添加自定义包头或填充。
- 发送中发生错误、超时或取消后，该连接不能继续用于发送或接收，必须重连。
- 注册连接失败时使用指数退避与抖动：首次 500–1000 ms，逐步增加，最高 15–30 秒。稳定连接 60 秒或手动重启后复位；手动重启会打断等待。
- 保留服务器的 15 秒空 Binary 心跳及客户端及时回复；不延迟屏幕、输入或文件数据。中继首消息保持 `RequestRelay`，不在之前发送 Ping。

**限制：16 KiB 是 WebSocket 帧限制，不是 TCP 包或 TLS record 限制。Schannel/Rustls 仍有各自的 TLS 指纹，没有实现浏览器 TLS 仿真、传输填充或实时数据时序伪装。** 服务器下行帧、15 秒心跳、持续远程桌面流量、IP 和域名等特征仍可被分析。仅修改客户端无法阻止域名/IP 封锁、TLS 检查或服务端主动探测。[TLS 1.3 的流量分析说明](https://www.rfc-editor.org/rfc/rfc8446#appendix-E.3)也说明了包长、时序及性能方面的限制。

## 构建

使用 `.github/workflows/custom-client.yml`。推送 `custom-wss` 分支、相关 PR 或手动执行时，先运行独立传输测试并生成 Flutter bridge，再构建三个目标。定制源码仓库为 [Caleb-Rainbow/rustdesk-client](https://github.com/Caleb-Rainbow/rustdesk-client)，完整构建结果以对应提交的 Actions 运行记录为准。

上游多平台工作流原文归档在 `.github/upstream-workflows/`，不作为可执行工作流加载；活动工作流仅保留定制构建入口。

工具版本保留于 `scripts/custom-toolchains.json`：Rust 1.85.1、Flutter 3.24.5（bridge 使用 3.22.3）、NDK r28c、cargo-ndk 3.1.2、固定 vcpkg 提交。编译主程序仍使用 `Cargo.lock`。

本地先检查工具：

```text
python scripts/custom-client.py doctor windows
python scripts/custom-client.py doctor android
```

准备好固定版本及本机构建依赖后：

```text
python scripts/custom-client.py bridge
python scripts/custom-client.py windows
python scripts/custom-client.py android
```

Windows 使用 MSVC 与 Flutter，产出完整 ZIP，必须解压全部 DLL/资源后启动其中的 EXE；面向 Windows 10/11 x64，未做 Authenticode 签名。Android 原生依赖使用 Linux x64 构建主机，产出两个 ABI 的 release 优化 APK。未配置正式签名时采用开发签名并明确标记；正式发行/覆盖升级需提供持久签名密钥。可配置 `ANDROID_SIGNING_KEY`、`ANDROID_ALIAS`、`ANDROID_KEY_STORE_PASSWORD`、`ANDROID_KEY_PASSWORD`，密钥不会进入源码附件。

构建输出保留于 `build/custom/`，包含源码、AGPL 许可、构建说明和 SHA256。源码来源与共享库冻结信息见 `vendor-manifest.json`。`hbb_common` 已纳入源码树，构建不依赖修改版子模块的外部发布。

```text

```

```powershell
$env:RUSTDESK_WSS_TEST_URL = 'wss://remote.yingluozhiwei.cn/ws/id'
cargo test --locked --manifest-path tests/wss-transport/Cargo.toml --lib verified_public_wss_handshake -- --ignored
```

覆盖：正确/异常部署 URL、明文 WS 拒绝、无效证书拒绝且不重试、TLS 整体超时、分片重组、Ping/Pong/Close、发送取消后断路、重连退避、旧服务端 WebSocket 0.17.2 的信令边界和双向各 1 MiB 中继。Rust 语法解析、工作流 actionlint 与 Python 脚本检查也已通过。

本机没有 MSVC/匹配的 Flutter/vcpkg 完整构建环境；完整客户端已在 GitHub Actions 构建，并下载到本地复核。
